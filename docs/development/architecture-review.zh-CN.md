# 当前架构、代码质量与前端方案评审

本文记录 `codex/migrate-dev-to-v0.12` 在医院部署目标下的当前状态，重点回答三个
问题：系统实际如何运行、哪些风险已经或尚未处理、现阶段是否应把 Gradio 迁移到
Vue。迁移历史和上游差异见 `fork-migration-v0.12.md`，部署操作见
`../deployment/hospital-intranet.md`。

## 1. 结论

- 当前代码已经建立在官方 `v0.12.0` 基线上，并把原 `dev` 的医院业务能力净迁移
  过来；没有把旧分支的生成物、缓存和备份重新带入。
- 运行架构仍然清晰地分成 `kotaemon` 核心 RAG 库、`ktem` 应用层和 Gradio 事件
  层。模型、索引、权限和持久化都在 Python 内完成，适合当前单机或单容器部署。
- 医院模式运行时只注册 GeekAI/其他 OpenAI 兼容过渡模型或内网模型，固定关闭 MCP、外部 Agent、
  Web 搜索、URL 入库、远程帮助、Gradio 分享和遥测。上游公共 Provider 的适配器
  源码仍在可复用核心库中，但不会进入医院运行对象；网络出口仍应由防火墙兜底。
- 现阶段不建议整体迁移到 Vue。应继续收敛 Gradio 页面，把“模型/索引/会话”业务
  逻辑保持在 Python 服务层。只有出现多团队并行、复杂移动端、前端独立发布或需要
  多副本实时会话时，再先抽 API、后分页面迁移，避免一次重写全部链路。

## 2. 当前逻辑架构

### 2.1 启动与页面装配

```text
run.sh
  -> hospital_preflight.py：账号、部署档、出口、离线资源、磁盘检查
  -> model_service_preflight.py：LLM/VLM、Embedding、Rerank、ASR 检查
  -> app.py
  -> flowsettings.py：功能开关、模型白名单、索引与存储配置
  -> ktem.main.App / BaseApp.make()
  -> 登录、辅助诊断、文件管理、资源管理、系统设置、帮助中心
  -> Gradio 事件声明、订阅、注册
```

`BaseApp` 负责注册推理管线、扩展和索引，并创建用户与设置状态；`App` 负责页面
编排及登录后可见性。开启用户管理时，普通医生只能进入诊断、设置与帮助页面，文件、
模型、用户、ASR 和声纹等管理能力只向管理员开放。

### 2.2 文档入库与检索

```text
上传文件
  -> FileIndexPage 参数与权限校验
  -> IndexDocumentPipeline
  -> Reader / 文档切分 / 元数据提取
  -> 默认 Embedding
  -> 文件存储 + LanceDB DocStore + Chroma VectorStore + SQLite 关系表
  -> 文件/分组选择器刷新

医生提问
  -> ChatPage.submit_msg 解析文本、图片和 @资料
  -> FileIndex 组合向量/关键词检索器
  -> Rerank
  -> FullQAPipeline 或 FullDecomposeQAPipeline
  -> LLM/VLM 流式生成
  -> 答案、引用、图表及会话状态持久化
```

图片输入在 `submit_msg` 中校验数量、类型、体积和像素，再以多模态消息交给 VLM；
Embedding 模型或向量维度变化时，旧向量库不能混用，必须重新索引。

### 2.3 模型边界

| 类别 | 当前实现 | 启动要求 | 后续内网替换点 |
| --- | --- | --- | --- |
| LLM/VLM | GeekAI `qwen3-vl-flash` | 文本和生成白图的视觉请求均通过 | OpenAI-compatible `/chat/completions` |
| Embedding | OpenAI 兼容适配，GeekAI 使用类型化输入 | 返回非空且维度为 2560 | `/embeddings`，切换后重建索引 |
| Rerank | OpenAI 风格鉴权与可配置结果映射 | 返回有效重排结果 | `/rerank`（非 OpenAI 官方标准） |
| ASR | Mock 多说话人事件流 | 明确跳过外部检查 | 实现现有 Provider 接口并配置院内地址 |

模型 Manager 只保存规格与默认项，实际组件按需创建；业务层不判断 GeekAI 或其他
厂商名称。环境变量中的真实密钥不得写入
仓库、日志或错误提示；过渡期图片和问题会发送到外部模型，必须先做脱敏与出网审批。

### 2.4 会话与 ASR

会话状态同时包含消息、检索证据、图表、索引选择和推理设置。修改或删除问题时会同步
截断对应的证据与图表，防止轮次错位。ASR 转写作为 AI 侧展示消息写入同一会话，但在
构造 LLM 历史时显式过滤，避免把转写卡片 HTML 当作提示词。

当前 Mock ASR 只验证流式事件、取消、说话人展示、权限和持久化，不代表真实录音、
切分、说话人分离或声纹算法已验收。真实协议确定后应只新增 Provider 适配器，不应
重新设计聊天事件链。

## 3. 本轮代码审计结果

| 级别 | 发现 | 处理或建议 |

| 已修复 | 1280 像素下主聊天区被双侧栏压缩到约 505 像素 | 证据面板按需打开，消息与输入区居中并限制阅读宽度 |

| 待上游升级 | Gradio/FastAPI 使用弃用的 `on_event`，Pydantic v1 风格 API 产生告警 | 当前锁定版本可运行；升级依赖时集中迁移，避免局部破坏兼容 |
| 待清理 | 上游 `ktem_tests/test_qa.py` 引用仓库不存在的顶层 `index` 模块 | 该孤立样例无法收集，不属于当前入库实现；后续上游同步时删除或重写 |
| 待集成 | ASR 仍为 Mock | 真实接口、音频传输、声纹授权和临床验收完成前不得标记为可用 |

直接删除会显著扩大后续合并冲突。医院版应通过配置白名单、页面入口、启动自检、
网络出口测试和防火墙五层限制确保不可达；如果未来独立发布医院专用 Python 包，再在
构建阶段裁剪依赖和模块。

## 4. UI 评审与本轮调整

参考成熟对话产品的“对话优先、输入统一、次要信息按需展开”原则，本轮没有照搬品牌
视觉，而是调整与医生任务直接相关的交互：

- 桌面端保留会话列表，参考证据默认关闭；左右入口固定在聊天画布，避免面板关闭后
  无法恢复。
- 消息区和输入区最大宽度统一为 980 像素。空会话说明支持文字、图片和知识库资料，
  同时明确模型回答只供临床参考。
- 空输入显示麦克风，有文字或附件显示发送；用户消息使用复制、修改、删除，AI 消息
  使用复制。触屏设备不依赖鼠标悬浮。
- 960 像素以下默认折叠会话列表，640 像素以下收紧留白；390×844 视口没有横向
  溢出，并可重新打开会话列表。

当前没有加入大面积动效、复杂图标库或前端状态框架，避免在内网弱终端和远程桌面环境
增加负担。后续优先级应是错误提示可行动、键盘可达性和真实医生任务测试，而不是继续
叠加装饰。

## 5. Gradio 与 Vue 决策

| 维度 | 继续使用 Gradio | 现在整体迁移 Vue |
| --- | --- | --- |
| 当前业务复用 | 直接复用 200 余条 Python 事件依赖和状态 | 鉴权、会话、上传、流式回答、引用、ASR 全部重写 |
| 部署 | 单个 Python 环境/镜像 | 增加 Node 构建、静态资源和 API 网关边界 |
| UI 自由度 | 中等，复杂 DOM 定制需谨慎 | 高，可建立完整设计系统和移动端体验 |
| 医院环境风险 | 当前已有回归基础，变更面小 | 双技术栈、接口安全和前后端版本兼容风险明显增加 |
| 长期扩展 | 适合单应用、低并发、快速迭代 | 适合多端、独立团队、高并发和前端独立发布 |

结论是继续使用 Gradio。Vue 的视觉上限更高，但“更好看”不足以抵消当前重写成本和
医疗场景回归风险。满足以下任意两项后再启动迁移评审：需要独立移动端；前后端由不同
团队发布；需要多副本实时会话；Gradio DOM 兼容层持续成为主要缺陷来源；无障碍或
复杂工作台需求无法实现。

建议的迁移路径是先把会话、文件、模型和 ASR 抽成带版本的 HTTP API，建立鉴权、
权限和流式响应契约；再从只读管理页开始迁移，最后迁移聊天页。迁移期间 Gradio 继续
作为可回退客户端，禁止一次性替换。

## 6. 当前验证基线

- `ktem` 应用层：92 项通过；孤立的上游 `test_qa.py` 单独记录，不掩盖收集失败。
- `kotaemon` 核心库：123 项通过，20 项因 PaddleOCR、Haystack、Unstructured 等
  可选依赖跳过。
- 全仓 Ruff、Python `compileall`、非压缩 JavaScript 语法、Shell 语法、`pip check`、
  `uv lock --check` 和医院 Docker Compose 配置均通过。
- 真实启动链路：医院静态自检 17 项通过、1 项 Mock ASR 警告；LLM/VLM、Embedding、
  Rerank 真实接口通过，Mock ASR 跳过；前台启动后首页返回 HTTP 200。
- 浏览器回归：1280×720 和 390×844 下验证默认布局、双侧栏、证据面板、图片入口、
  文本/语音按钮切换及移动端无横向溢出。

上线前仍需使用院内脱敏样本完成 PDF、DOCX、XLSX、图片问答和权限验收，并在真实
ASR 接口接入后补充音频质量、说话人分离、取消、超时和断网恢复测试。
