# 医院内网版重构提交记录

本文件按 Git 提交逐项记录本地化重构的改造动机、范围和注意事项。Git
提交信息统一使用英文，本文件使用中文说明，便于医院信息科、运维和后续开发者
追溯变更。

## `feat: add traceable user notifications`

- **改造动机**：原聊天链路只捕获 `ValueError` 并打印到终端。模型连接失败、超时
  或其他异常会直接中断页面，医生只能看到笼统的 Error，运维也无法将页面报错与
  服务端日志对应。
- **改动范围**：新增统一通知模块，为非预期异常生成短故障编号；页面展示经过
  脱敏的中文原因和处理建议，服务端日志保留故障编号及完整堆栈。新增滚动日志
  配置，默认写入应用数据目录的 `logs/app.log`。
- **聊天容错**：主回答失败时保留已生成内容并附加错误说明；会话自动命名和推荐
  追问改为失败后降级，不再影响已经生成的答案；空问题改为明确中文提示。
- **注意事项**：故障编号只用于关联日志，不包含用户、病历或模型密钥信息。可用
  `KH_LOG_LEVEL`、`KH_LOG_MAX_BYTES` 和 `KH_LOG_BACKUP_COUNT` 调整日志级别与
  保留策略。

## `feat: localize and refine the clinical interface`

- **改造动机**：医生端和管理员端存在中英文混排，部分按钮、表头、内容类型和
  模型连接状态含义不明确；聊天区、文件区与证据区的视觉层级也不够稳定。
- **改动范围**：增加轻量中文文案表，在不改变选项内部值的前提下翻译动态设置；
  统一聊天、文件/分组、索引、LLM、Embedding、Rerank、帮助页等核心界面的
  中文按钮、表头、状态和操作提示。
- **界面调整**：增加独立医疗场景样式文件，改善左右侧栏、聊天气泡、输入区、
  文件表格和移动端布局。样式复用现有 Gradio 主题变量，不引入新的前端框架。
- **兼容说明**：模型名称、供应商类名、YAML 参数名等技术标识保留原文；翻译后的
  下拉选项只改变显示标签，不改变数据库和推理管线使用的值。

## `fix: harden credentials and document rendering`

- **改造动机**：原系统将用户名和密码同时写入浏览器 `localStorage`，密码使用无盐
  SHA-256 保存；上传文档中的原始 HTML 还可能进入证据面板，存在凭据泄露和存储型
  XSS 风险。
- **密码改造**：浏览器只记住用户名，不再保存或自动回填密码；新建和修改的密码
  使用带独立随机盐、60 万次迭代的 PBKDF2-SHA256。历史 SHA-256 密码仍可验证，
  并在用户首次成功登录后自动升级，不需要统一停机迁移。
- **内容安全**：文档正文进入 Markdown 渲染前先转义原始 HTML，文件名、页码预览
  属性、图片标题和高亮文本分别按 HTML 文本或属性规则转义，阻止文档脚本在其他
  用户浏览器执行。
- **注意事项**：本提交不改变现有用户名和用户 ID，也不会在日志中记录明文密码；
  SSO 创建的无本地密码账号仍只能通过 SSO 登录。

## `feat: add hospital deployment profiles`

- **改造动机**：医院环境不能依赖公网 CDN、GitHub、NLTK/tiktoken 临时下载或
  Chroma 遥测；数据库中历史公共 Provider 即使不再显示，也会在启动时被模型
  Manager 反序列化并可能联网。
- **部署档位**：新增 `hospital-external` 和 `hospital-offline`。前者仅允许白名单
  HTTPS 模型域名和内网地址，后者仅允许回环、私网 IP、单标签服务名及
  `.local/.internal/.lan` 地址。医院档强制关闭 MCP、网页抓取、外部 Agent、远程
  帮助、Gradio API 展示和遥测。
- **资源本地化**：固定并内置 Tribute、MiniSearch、D3、Markmap 依赖；PDF 预览
  改用随包 PDF.js，首次运行只解压本地归档；内置 LlamaIndex 所需 NLTK 英文数据，
  同时提供不下载词表的本地 Token 估算器。
- **模型白名单**：医院模式只加载当前配置档声明的 LLM、Embedding 和 Rerank。
  旧公共 Provider 记录保留在数据库但不实例化；管理员新增模型时同样执行地址
  策略校验，避免通过自定义 Base URL 绕过出口限制。
- **配置模板**：新增 `.env.hospital.example`，分别给出 GeekAI 过渡档和最终内网
  OpenAI-compatible 模型网关配置。真实密钥和管理员密码不得提交到 Git。

## `fix: harden file indexing and archive uploads`

- **改造动机**：上传索引的总异常会直接把底层异常展示给医生，单文件失败数量还
  错误地统计了上传前校验结果；快速上传失败时可能继续拼接空返回值，引发二次异常。
- **错误反馈**：索引总异常和逐文件异常统一生成故障编号，页面仅展示中文说明，
  完整堆栈写入滚动日志；完成提示按索引管线的真实失败结果统计。快速上传在失败时
  返回空结果，不再遮盖首次故障。
- **压缩包安全**：每次上传使用独立临时目录，避免并发用户互相删除解压文件；拒绝
  路径穿越、绝对路径和符号链接，并限制文件数量及解压后总大小，处理结束自动清理。
- **配置项**：`KH_ZIP_MAX_FILES` 控制单个压缩包最多文件数，
  `KH_ZIP_MAX_SIZE_MB` 控制解压后总大小；默认分别为 200 个和 500 MB。

## `fix: improve database and indexing reliability`

- **改造动机**：SQLite 默认锁等待较短，多名医生同时保存会话、设置或索引时容易
  出现 `database is locked`；快速上传又会把向量写入放到无返回通道的线程，页面
  可能在 Embedding 实际失败前显示成功。
- **数据库加固**：SQLite 连接启用 30 秒忙等待、跨线程连接、外键约束、WAL 日志
  和 `NORMAL` 同步级别，在保持单文件部署方式的同时改善读写并发。非 SQLite
  数据库不改变现有连接行为，可用 `KH_SQLITE_BUSY_TIMEOUT_MS` 调整等待时间。
- **索引一致性**：医院部署档的快速上传仍使用默认解析器，但 Embedding 与向量库
  写入改为请求内同步执行；失败会沿现有故障编号链路返回页面，不再出现后台静默
  失败或“先成功、后缺向量”的状态。
- **数据模型**：JSON 字段改用独立默认工厂，避免会话、用户设置、问题报告和索引
  配置在进程内意外共享同一个可变默认对象。

## `feat: add hospital deployment preflight checks`

- **改造动机**：迁移到另一套内网环境时，密钥占位符、弱启动密码、错误模型地址、
  公网功能开关或缺失静态资源通常要等应用启动失败后才能发现，定位成本较高。
- **自检范围**：新增不访问模型服务的启动前检查，验证部署档位、模型配置、地址
  白名单、首次管理员密码、公共 Provider 遗留密钥、外部功能开关、离线前端/PDF/
  分词资源、数据目录写权限和剩余磁盘空间。
- **运维入口**：`./run.sh doctor` 输出逐项 `[PASS]`、`[WARN]`、`[FAIL]` 和汇总，
  失败时返回非零状态，便于部署脚本或 systemd 在启动前阻断错误配置；输出不会打印
  任何密钥或密码内容。
- **兼容说明**：已有用户数据库时允许不再保留启动管理员明文密码，但会提示确认
  管理员账号可用；ASR 开启但没有服务地址时仅警告当前将使用 Mock Provider。

## `feat: add one-command hospital deployment`

- **改造动机**：直接在医院服务器运行 `uv sync` 或 Docker 在线构建仍会访问软件源，
  且容易因机器环境差异产生不可复现的问题；手工启动也缺少固定的数据挂载、健康
  检查和回滚入口。
- **镜像交付**：新增医院专用多阶段 Dockerfile，在联网构建机固定 Python 和 uv
  版本并安装文档解析运行库；最终镜像内已包含 Python 依赖、PDF.js、NLTK 和浏览器
  资源，运行阶段不下载依赖。构建上下文明确排除真实 `.env` 和应用数据。
- **一键启动**：新增 Docker Compose 和 `deploy_hospital.sh`。配置完成后，一条命令
  会先执行医院自检，再以 `--pull never` 启动固定镜像；也保留已准备好虚拟环境时的
  原生部署方式。数据统一持久化到项目根目录 `ktem_app_data`。
- **安全与运维**：容器使用宿主当前 UID/GID、丢弃 Linux capabilities、禁止权限
  提升并内置健康检查。新增中文手册说明联网构建/内网运行边界、镜像校验、模型
  切换、故障编号、备份、升级、回滚和上线验收清单。

## `fix: disable framework network checks`

- **改造动机**：完全断网启动回归发现，虽然业务功能和静态资源均已离线化，Gradio
  仍会在后台线程获取官方提示文案；Hugging Face/Transformers 组件在缓存缺失时也
  可能尝试下载模型或数据集。
- **改动范围**：医院模式在任何 Gradio 页面构建前关闭 Analytics/在线文案更新，
  同时启用 Hugging Face Hub、Datasets 和 Transformers 离线开关；Docker 运行镜像
  也显式固定相同环境变量，避免入口脚本差异绕过设置。
- **验证结果**：使用 Socket 拦截器构建完整 UI（423 个组件、247 条依赖）时，模型
  池仅保留 GeekAI 配置、MCP 关闭、页面 Head 不含公网 URL，后台网络连接尝试为 0。

## `chore: remove public provider defaults`

- **改造动机**：通用 `.env.example` 仍沿用上游模板，列出了 OpenAI、Azure、
  Cohere、Voyage、GraphRAG、Adobe 和 Google 登录等公共服务。医院模式虽不会加载
  这些配置，但实施人员复制模板时仍可能误配或误以为系统需要通用互联网出口。
- **配置收敛**：通用模板改为医院档，默认只声明 GeekAI 过渡模型、最终内网模型
  网关示例、可选内网 Keycloak、离线资源和运行容量参数；删除所有无关公共 Provider
  密钥字段与公网地址。上游 Provider 适配器源码不删除，便于后续 rebase，但医院
  模式的 Manager 白名单仍确保它们不会实例化。
- **文档入口**：中文首页改为复制 `.env.hospital.example`，要求启动前运行
  `./run.sh doctor`，并链接医院离线构建、备份和回滚手册。
